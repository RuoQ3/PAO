# 参数影响回测：故障修复与验证

针对 `docs/报错.txt` 中的执行记录，本次修改覆盖计划、执行、分析和对话输出。

## 行为变化

- `ConversationSession.submit()` 的确认分支统一返回 `Answer`，并将结果摘要与失败原因写入会话历史；原始工况和敏感性结果保存在 `Answer.facts` 的 `action_result` 中。
- 动作执行异常转为失败回复，清除待确认状态，避免重复确认再次执行；网关原有审计保留。
- 参数扰动裁剪到上下界后按完整输入向量去重，再检查预算。日志中的 11 个工况变为 9 个独立工况。
- 首个基准工况不收敛，或其目标指标缺失/非有限数时，停止后续扰动；报告区分计划数量、已运行数量、收敛数量、有效指标数量与未执行数量。
- 保留全流程收敛检查。T0302 出错时不会因为 T0301 成功就接受该工况。
- `STR_MAIN` 通过物流子树提取器读取，不作为标量 Value 输出读取；真实 `ProcessCase` 依据 `plan.output_spec` 提取指定物流和组分，禁止默认改用第一条物流。
- 真实仿真错误从 `sim_result.error`、warnings 传到报告，包括底层能提供的 Aspen history 诊断。
- 敏感性分析按“基准＋仅此参数变化”的工况分组，去除重复取值，剔除缺失、NaN 和 Infinity 指标。取消仅凭样本数给出的 high/medium 置信度，结果不声称统计显著性。
- 同时展示分析异常与仿真失败，避免把分析异常误报成单纯样本不足。
- 助手自己的回答不再更新用户关注指标；缺少指标时提示中文选项。参数影响计划展示规则降级原因，分类器记录具体异常；提示词明确包含 analysis 字段。
- CLI 不再重复打印审批计划的整份内部字典，修复问号占位文案。

## 验证

运行 `python -m pytest -q`：128 passed，1 skipped。
新增 15 项回归测试，包括真实 ProcessCase 适配、模拟驱动清理、基准预检、单因素统计和 CLI 确认后继续对话。

测试环境为 Linux/Python 3.12，使用假仿真及模拟驱动；未运行 Windows Aspen COM。现有 B:F 授权边界未放宽。

## Windows 现场复测

1. 使用原来的 CLI 启动命令。
2. 明确提问：“针对 T0301，哪些参数对 0319 物流中 ADN 的摩尔分数有影响？”
3. 检查预览应为 9 个独立工况，再输入“确认”。
4. 若 T0302 仍失败，应只运行基准工况，显示 T0302 错误和其余 8 个未执行工况，随后仍可输入新问题。
5. 在 Aspen 中检查 T0302 的具体错误和基准模型设置；修复收敛后重新创建并确认计划。
6. 成功运行后核对提取值是否为 0319/ADN 摩尔分数，并检查分组后的独立取值数。

代码修复不能证明 T0302 的工艺模型已收敛；详细 Aspen 错误未提供时，不推断其物理原因。

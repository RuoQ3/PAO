# 对话优化与算法选择

对话中明确选择的算法优先于 YAML。未指定算法时使用所选配置中的算法，并在计划中标明来源。
分类协议 `optimization_request.analysis` 保存算法、设备、组分、物流、指标、目标、执行预算、
显式优化参数和随机种子；普通优化请求不再通过 LLM 动态生成必填字段。
可选的 execution、optimizer_parameters、random_seed 返回 null 时按未提供处理，继续沿用项目配置；
同一规范化规则用于意图响应、checkpoint 恢复和计划生成。字符串、数组等非法对象类型仍拒绝。

例如：

```text
使用遗传算法优化 T0301，使 ADN 纯度达到 99.99%。
总评估最多 80 次，总时限 3600 秒，最多失败 10 次。
```

`GA`、`genetic algorithm`、`遗传算法` 对应 pymoo 单目标 GA。它不会自动变成 NSGA-II。
在上述明确的纯度目标下，计划将唯一匹配的产品组成下限改为 `0.9999`，并生成最大化该产品纯度的
单目标 GA 问题。原 YAML 中的产量/能耗目标被本次对话目标替代，此变化显示在审批预览中。
质量/摩尔基准来自匹配的 MASSFRAC/MOLEFRAC 路径；无法唯一匹配时继续澄清。
纯度下限支持 `0.9999以上`、`99.99%以上`、`不低于99.99%` 和 `>=0.9999`，
百分数使用十进制精确换算。上限、范围、近似值和多数字文本不会被截取成下限。
无效目标在收集预算前即进入目标澄清；后续回答可修复原目标，并保留已确认的算法和预算。
等值写法（如 `0.9999以上` 改写为 `99.99%`）可直接采纳，实际改变有效阈值仍需明确更正。
多目标遗传优化应明确选择 NSGA-II；当前 NSGA-II 适配器仍只支持连续变量。

GA 使用 pymoo 0.6.1.5，支持连续/整数混合变量、单目标、有限工程边界和不等式约束。
初始化采用 FloatRandomSampling；交叉 SBX、变异 PM；整数列在初始化、交叉、变异中使用
numpy.rint 修复，实际输出仍重新校验整数类型及边界。默认种群 20，代数 10，交叉概率 .9、
交叉 eta=15、变异 eta=20、每变量变异概率 .1；最终参数写入审批身份。纯度分数约束缺少 scale 时
使用 1，表示原始分数残差；其他量纲的约束仍需显式 scale。不支持派生变量、动态缩界或运行恢复。
从 BO 切换到种群算法时，禁用的 BO 策略列入预览。

预算沿用有效项目配置，用户明确提供的值覆盖配置。缺少总评估次数、总时限或最大失败数时，
保留原任务并询问；支持短回答、改口及 checkpoint 续接。每代前检查剩余额度，不足一代则停止。
可通过后续对话更正算法、目标、预算、pop_size 和 generations。
`generations` 包含初始代，20 个个体 × 10 代的计划评估数是 200，不额外加初始种群。
`200代` 保存为 generations=200，不转换为总评估200次。回复会说明两者分别设置；
审批预览显示计划评估数，以及预算不足时最多支持的完整种群数，保留用户指定的代数与预算。
顾问上下文中的 configuration/objectives/constraints 展示本次生效值，source_configuration 保存原 YAML，
避免旧注释与对话覆盖值混为冲突。单目标纯度最大化与纯度下限可以并存，GA 不要求梯度。

对话配置保存在计划的 `configuration_overrides`，不修改源 YAML/BKP。
预览、批准时验证和执行加载使用同一覆盖配置；模型、源文件、目标、参数、算法及预算均受审批摘要绑定。
配置、算法依赖或变量类型不兼容时返回具体原因，保留原算法选择，未调用 Aspen。

其他任务的通用 `task_fields` 协议仍严格校验字段和证据。一旦字段名不一致、存在未声明参数、
字段定义非法或 JSON 错误，最多修复一次；失败后停止。文件日志记录脱敏原始响应，
会话审计记录缺失字段、未声明参数和重试次数。

优化顾问的最终回答若未通过证据/格式校验，允许一次仅生成文字回答的修复，不重放工具或提交审批。
原始标量组成不等于完整 metrics 证据元组；模型自行计算的差值不能伪装成已验证测量。
仍不合格时拒绝该回答、保留算法/目标/预算，用户可继续修正条件或要求重新生成计划。
真实服务不可用、超时及工具权限错误仍停止请求。静态快照不能证明 99.99% 可达或不可达。

自动测试包含真实 pymoo 数学测试、假 LLM 对话测试、CLI 预览与模拟驱动执行测试。
自动测试不会调用真实 LLM、Aspen 或 COM。

真实 Aspen 验收配置：`cases/demo_case/ga_purity_config.yaml`。每代4个个体、2代，
8次评估、600秒、最大失败4次；保留原模型、T0301硬边界、输入回读和收敛检查。
仅提取声明的标量输出，`extraction.blocks: []`、`streams: []` 跳过可选全树遍历；
未指定这些字段仍按原行为自动枚举。该配置的可复跑命令：

```powershell
python -m src.main cases/demo_case/ga_purity_config.yaml --conversation
```

对话中说明“GA优化T0301，ADN质量分数达到0.9999以上，种群4、2代、8次评估、600秒、最大失败4次”，
审核预览后输入“确认”。普通确定性入口省略 `--conversation`，预览后输入 `APPROVE`。
真实运行中8次均收敛但未满足纯度下限，最高质量分数0.999858483；这不证明目标在整个硬边界内不可达。
可行性不满足但目标/约束输出完整的工况不消耗仿真失败额度，仍消耗总评估额度。
真实失败和指标缺失仍计入失败额度。

LLM常见的 `population_size` 别名规范化为 `pop_size`；明确冲突时拒绝。
优化顾问拥有180秒的总任务时限，单次传输超时仍独立生效。证据引用修复请求包含全部非法路径，
执行后分析也允许一次纯文本修复；此重试只解释已保存证据，不重放工具或重新执行 Aspen。
